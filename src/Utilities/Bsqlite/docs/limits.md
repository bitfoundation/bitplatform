# Limits

What the browser cannot do, what Bsqlite keeps the same on a device, and how the library tells you.

| Limit | Behaviour |
|---|---|
| Synchronous ADO.NET and EF members (`Open`, `ExecuteReader`, `SaveChanges`, `ToList`, `EnsureCreated`) | Throw `BsqliteSynchronousApiNotSupportedException` naming the async overload. The worker cannot be waited on from the main thread. |
| `PRAGMA journal_mode = WAL` | Rejected on every backend. No web VFS provides the shared memory WAL needs. Journal mode is `DELETE` or `TRUNCATE`. |
| `ATTACH` | Rejected when the backend declares `SupportsMultiDatabaseTransactions = false` (OPFS). Open each database on its own session. |
| `PRAGMA page_size = …` | Rejected when the backend declares `CanChangePageSize = false` (IndexedDB, Cache Storage). |
| Command timeout and `Cancel()` | Not enforced on a running statement: a cancellation token stops the caller waiting, and the statement runs to completion in the worker. The timeout does bound the wait for another context's transaction, after which the command fails with `BsqliteConcurrencyException`. |
| Contexts of one session | Share the session's connection and take turns: a transaction keeps every other context waiting until it ends - see [Concurrent contexts](getting-started.md#concurrent-contexts). Code holding a transaction that waits on another context gets "database is locked" once the timeout runs out. |
| SQL the engine supports | SQLite 3.53: common table expressions (recursive too), window functions, UPSERT, `RETURNING`, generated columns, JSON and JSONB functions, the math functions, foreign keys, triggers, views, savepoints. Not built in: full-text search (FTS3/4/5) and the R*Tree - `CREATE VIRTUAL TABLE` fails with "no such module". `generate_series` is not available either. The E2E suite pins this list (`EngineTests`). |
| Database name length | Up to 504 bytes of UTF-8 for the full path SQLite hands the VFS - the name with a leading `/` - on OPFS, IndexedDB and Cache Storage. Bsqlite registers their VFSes with a 512-byte path limit (wa-sqlite's default is 64), and SQLite keeps 8 of those bytes for the `-journal` suffix of the rollback journal's name. |
| Declared column types from `GetDataTypeName` | The engine is built with `SQLITE_OMIT_DECLTYPE`; the worker reports the storage class of the first row (`INTEGER`, `TEXT`, …). EF Core is unaffected. |
| `EnsureDeletedAsync` | Drops every view and table and runs `VACUUM`; it cannot unlink the file while the session holds it. Use `BsqliteDatabase.DeleteAsync` to wipe storage. |
| Snapshots on IndexedDB and Cache Storage | `ExportAsync` of an open database there is a compacted copy (`VACUUM INTO`) rather than the file byte for byte: the asynchronous engine builds cannot read pages from storage inside `sqlite3_serialize`. The schema, rows, `user_version` and `application_id` are the database's. |
| Transaction isolation | SQLite has one isolation level for a connection's own transactions, serializable. `Serializable` and `Unspecified` begin with `BEGIN IMMEDIATE`, taking the write lock up front; any other level begins deferred, which can fail with `SQLITE_BUSY` the first time it writes if another tab writes first. |
| Unnamed `?` parameters on a device | The worker binds an unnamed parameter by its position. In a Blazor Hybrid app the native transport runs Microsoft.Data.Sqlite, which binds by name only, so name every parameter (`@p`, `:p`, `$p`, or `?1`) in code that runs on both. |
| Firefox and Safari | Supported through the Asyncify build for async backends; OPFS synchronous access handles need a recent version. The browser suite runs on Chromium by default; set `BSQLITE_E2E_BROWSER=firefox` or `webkit` to run it on either, after installing that browser for Playwright. |
| Blazor Hybrid | The same rules hold on a device - async members only, no WAL - so one code path serves both hosts. JavaScript extension modules (`AddExtensionModule`) do not load in-process; they are skipped with a logged warning, and SQL that calls their functions fails with `no such function`. |
| Interactive Server | Not supported. A user's database lives in their browser, or on their device in Blazor Hybrid; the `file-system` backend is never offered to a server, which would share one file between every user. Run the pages that use the database on WebAssembly - in the `.Client` project, with `@rendermode InteractiveWebAssembly` - and keep Interactive Server for the rest of the site; data that belongs on the server goes in a server database, such as `Microsoft.EntityFrameworkCore.Sqlite` registered with `AddDbContextFactory` for the server host. |

Guards run on both sides: the .NET command layer rejects the statement before it leaves, and the worker rejects it again so a JavaScript caller cannot bypass the capability declaration.
